# One-Contract

面向律师、法务和合同高频处理团队的**原则型、修订优先**合同审查与起草 Skill。它从交易目的、权利义务、失败模式、证据状态和条款联动出发，优先把能负责任落文的方案写成真实 Word 修订，并以批注承载事实、授权和重大选择。

> 目标不是堆叠规则命中或风险报告，而是交付可接受、可拒绝、可回滚、可验证的合同修改。

## 适合谁用

- 需要高频审查中文商业合同的律师、法务和律所团队
- 希望统一审查口径、风险分级和 Word 交付格式的团队
- 需要从零起草合同，并先固定交易文件包、程序前提和待补事实的人

## 典型场景

```text
用户：请站在采购方立场，以常规口径审查这份设备采购合同，重点关注标的规格、验收、付款和违约责任。
AI：我会先确认审查立场和口径，再按交易结构、证据状态和条款联动识别风险。
    交付物包括审查报告，以及带真实修订和批注的 Word 文件。
```

## 它能产出什么

- **风险清单**：风险等级、后果、判别标准、相关条款、整改建议
- **推荐措辞**：可直接谈判或落入合同正文的条款文本
- **审查报告**：可签结论、先决事项、谈判优先级和复核要点
- **Word 修订批注版**：在 `.docx` 中直接显示修改痕迹和批注（真实 `w:ins`/`w:del`）
- **接受/拒绝修订副本**：自动生成接受全部修订与拒绝全部修订版本，供复核
- **起草工作台**：主合同类型、配套协议、必带附件、待补事实和条款骨架

## 核心方法：原则型、修订优先

One-Contract 不把知识提炼成大量机械 if-then 规则，而是提供一套接近资深律师带教的工作方法：

- **识别交易目的与失败模式**：先理解交易想实现什么、可能在哪里失效，再审查条款；
- **证据状态分级**：`confirmed / reasonable_assumption / major_choice / not_applicable` 决定直接修订、修订加批注、仅批注或不输出；
- **专业默认与推翻因素**：给出"通常如何处理"以及"什么因素足以推翻默认"，Agent 对具体交易重新推理，不被模板锁死；
- **修订优先、批注兜底**：能负责任落文的直接修订；事实尚缺但可合理假设的修订并批注；必须由客户作重大决定时才仅批注。

**通用条款原则与专项资产的关系**：跨类型通用条款（管辖、付款节奏、通知送达、合同变更等）由通用原则统一处理；专项合同类型资料（原则卡/模块）在通用原则的**硬边界内深化**该类型的审查方向。专项的场景化深化优先，但不得突破法律与动作边界。

## 当前覆盖范围

采用 **企业合同分类体系 v2**（EC-01 ~ EC-10 十大类，永久 `type_id`）。首批 20 个类型中，已有 **5 个类型正式激活**为可直接用于正式审查的 `active` 资产：

| 类型 | 状态 | 资产 |
|---|---|---|
| 股权转让（EC-01-001） | ✅ 已激活 | 原则卡 + 8 模块 + 触发器 + 经验卡 + 联动组 |
| 设备、原材料采购（EC-02-002） | ✅ 已激活 | 原则卡 + 5 模块 + 触发器 + 经验卡 |
| 协商解除劳动关系（EC-06-004） | ✅ 已激活 | 原则卡 + 5 模块 + 触发器 + 经验卡 |
| 员工保密（EC-06-002） | ✅ 已激活 | 原则卡 + 5 模块 + 触发器 + 经验卡 |
| 竞业限制（EC-06-003） | ✅ 已激活 | 原则卡 + 5 模块 + 触发器 + 经验卡 |

其余类型保持候选框架，可通过 `select_active_assets.py` 只加载 `active` 资产；无激活资产时按通用原则型方法审查，不把候选资料包装成正式知识。

支持：

- 甲方、乙方、中立等审查立场
- 克制、常规、强势等审查口径
- 仅批注、直接修订、批注与修订结合等落痕策略
- DOCX 原生批注、修订和 Word 审查意见书输出

## 劳动人事专项

协商解除劳动关系、员工保密、竞业限制三类劳动人事合同已深度激活，覆盖：

- **协商解除**：解除路径/提出方、经济补偿依法、结算分项、社保/证明/档案程序义务、特殊保护（工伤/职业病/医疗期/孕期）、权利终结范围；
- **员工保密**：保密范围与岗位匹配、在职/离职义务、资料返还/删除/账号退出、职务成果衔接、违约救济；
- **竞业限制**：主体适格性、期限≤二年、按月补偿、启动/解除机制，并区分**法律强制边界**（期限≤二年、人员适格）与**指引建议**（人社部竞业合规指引的补偿/违约金比例，非强制）。

## 安装方式

1. 打开本仓库的 GitHub Releases。
2. 下载最新版本的 skill 压缩包。
3. 解压后将 `one-contract/` 文件夹放入你的 skill 目录。
4. 在支持 `SKILL.md` 的 Agent / Claude 环境中启用该 skill。
5. 如需生成 Word 批注、修订或报告，安装脚本依赖：

```bash
pip install -r scripts/requirements.txt
```

首次生成审查文件时，按 Agent 提示确认审查人姓名和机构；配置会写入本地 `config/`，不会作为公开发布内容使用。

## 使用边界

这个 skill 适合：

- 中文商业合同的常规审查、起草和交付格式统一
- 批量合同的一轮风险扫描和修订底稿生成
- 律师或法务复核前的结构化整理

这个 skill 不适合：

- 替代律师对重大交易作最终签署意见
- 处理未提供事实背景、交易安排或业务目标的合同
- 覆盖所有涉外法域、外文合同和高监管行业专项审查
- 自动完成需要线下审批、登记、备案或主体授权核验的事项

## 核心设计

### 最终文件质量门

DOCX 执行后必须重新打开最终包，检查全部 XML/RELS、编码、关系、评论锚点和修订属性，并生成接受版与拒绝版。执行器返回成功不等于完成；任一 finding、结构门、语义视图或渲染门失败都应阻断正式交付并保留失败证据。

### 分析与文档操作分工

Agent 负责识别风险、形成审查计划和推荐措辞；脚本负责在 DOCX 中稳定写入批注、修订和报告，减少复制粘贴导致的格式错误。

### 知识路由与激活管理

企业合同先按分类体系 v2 识别类型（`enterprise-taxonomy-v2.md`），再通过 `modular-knowledge-routing.md` 检索对应原则卡和条款模块，只加载 `active` 资产。候选/律师批准/回归通过状态的资产不进入正式审查。

### 记忆但不静默代填

本地配置可记住审查人、客户和审查口径，但新环境或缺少关键身份信息时仍会要求确认，避免把历史配置误用到正式交付。
