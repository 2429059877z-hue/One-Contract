# Studio 操作说明

本说明对应 2026-10-21 的 3.3-preview 预发布。工作台在本机运行，客户数据保存在 Skill 目录之外。开发测试、离线包组装和律师生产验收是不同阶段；当前尚无原生 Windows 与 Word/WPS 的最终验收结论。

## 找到并读懂规则

“规则总览”先以星云图展示全部业务大类。选择大类后进入树状图，继续按合同类型找到原则与条款模块，再打开完整正文。可以随时返回总览，保留当前类型和已选客户。图与下方目录使用同一份真实数据，包含尚未启用或没有完整专项内容的类型；列表可以搜索和翻页，类型覆盖不足会明确显示。

查看共享模块时，图中列出它的全部已声明位置。选择另一个适用类型，仍查看同一模块，并更新该类型下的依赖解释。位置连线表示关联，不代表优先级或实际启用；客户补充规则、公共修改建议和填写进度仍在各自区域中核对。

打开规则后阅读完整目标、适用条件、审查要求、处理文本和依据。来源、依赖与反向引用可以继续定位；共享模块的多个业务位置指向同一模块。切换合同类型会同时切换该类型下的依赖解释。

候选正文供维护者阅读与修改，不因此参与正式审查。来源节点显示来源核验记录，不能把来源核验与规则启用混为一谈。

需要查看顾问单位口径时，明确选择客户。当前草稿与已启用快照分开显示：修改草稿不会改写已经启用的内容。目录中的位置只说明声明的适用范围；“试运行”展示进入审查输入的规则和判断提示，客户规则是否在具体合同中适用，由审查 AI 结合全文判断，不能把试运行结果当作最终适用结论。

## 新增、复制和修改

从当前目录位置新增，或从类似规则的详情复制。公共规则建议与客户专属规则分别维护。大类原则、具体类型原则、条款模块和客户规则使用不同字段，不需要自行猜测编号或审核字段。

字段按六组组织：身份与定位、适用范围、条件与边界、审查要求与处理、依据与关联、验证与发布。每项标明必填、条件必填、可选或系统记录，并给出含义和示例。示例不会自动成为交易事实或审核结论。

依赖和关联规则可以按名称搜索选择；共享模块可以分别选择某个合同类型及其前置模块，不必手填技术编号或整段 JSON。客户规则的条款议题提供中文受控选项。已有记录中的未知编号或历史值会保留并提示核对，不会因为当前选项中没有它就自动清空；仍须通过实际引用和语义检查。

客户规则的适用条件可选择“由 AI 结合合同全文判断”，在条件说明中保留完整自然语言，例如“乙方且为收款方时”。这种方式须有完整说明，不能同时混入结构化条件条目；原有条目会保留供核对，不会自动删除。

也可明确选择有结构化事实条件、在适用范围内不另设事实条件，或尚未确定。“尚未确定”可以保存填写进度，不能作为完整规则提交。结构化多条条件还须选择全部满足或任一满足；受控事实与处理目标决定比较值的类型。这些业务条件的预筛结果仍交全文 AI 判断，不要求每份合同再次逐条点击人工确认，也不能把未知事实编成否定值。

“保存填写进度”保留尚未写完的正文及表单位置，并列出缺项；该记录不进入可执行规则库。重新载入旧进度时，如对应正式草稿已由其他操作修改，系统会拒绝覆盖。填写完后再“保存为草稿”或“保存修改建议”。

公共建议和公共填写进度会按已经明确填写的业务位置，列在目录的“尚未启用”区域；可以查看完整内容并返回原记录继续编辑。未填写或无法核对的位置不会被系统猜测，可从公共建议页的列表找回。客户填写进度只在已选客户的维护页中载入。

保存前使用“预览位置、条件和处理要求”，核对业务位置、角色和阶段、事实条件、处理动作、依据和缺项。格式检查通过不等于法律判断正确。编辑已有规则时，未编辑的条件、理由、有效期、依赖和其他原字段保留原值。

也可以先提出自然语言要求并附上材料，让当前使用的外部 AI 整理，再回到 Studio 核对候选全文、来源对应和待确认问题。Studio 本身不内置模型，不会自动执行 AI 或代填确认。反馈后由 AI 读取最新版本继续整理；明确采用候选后，仍进入现有保存、审核和启用流程。操作步骤及 AI 命令见 [AI 整理，Studio 核对](studio-ai-authoring.md)。

## 客户规则审核、测试与启用

保存的规则仍未启用。送交复核并由操作者明确记录律师确认后，编写测试情形：合同类型、角色、阶段、场景、真实事实，以及预期是否交给 AI 审查、声明的处理动作和是否存在须先处理的阻断。这里的正式规则确认，与单份合同的适用性判断是两件事。

测试会真实调用正式解析器，显示预期与实际差异，并把执行证据绑定到当前内容。应覆盖业务范围匹配、不匹配、事实缺失以及用户明确限定审查范围等情形。业务预筛不匹配或事实未定时，规则可以仍进入 AI 审查待办，并带出具体判断提示；只有真实的范围或治理限制才按对应理由排除。测试通过不证明最终合同适用性或正文已经落实，未覆盖的事实组合也不会自动得到保证。

同时启用多条规则时，载入完整的已确认规则集合，逐条明确每个场景应交给 AI 审查哪些规则及其声明的处理动作，再运行整组测试。单条分别通过不能替代整组验证。修改内容或最新测试失败会撤下发布资格；既有启用快照保持原样。

完成测试后，核对待启用集合并明确启用。恢复点保存当前版本；恢复到上一版本以不可变快照链为准。若出现“写入已提交、恢复记录待完成”，先刷新并核对状态，不把它当作完全未写入反复发布。

## 试运行与条款类别

“试运行”按实际输入列出进入审查的规则、排除原因、冲突和全文判断提示。客户的业务提示不阻断其他可落实修订，也不表示已作出最终适用结论。明确选择客户后，如其快照缺失、损坏或与当前公共规则不兼容，不会静默退回仅公共规则。

我方身份、合同阶段、业务情形与规则编辑使用同一份选项目录。例如设备租赁可以选择“承租方—履行—返还”；“交割”属于业务情形，合同阶段应另按真实情况选择。仅改变角色、阶段或场景，不再一律自动排除客户规则，实际不一致会作为全文判断提示保留。选项尚未读取完整或读取失败时，页面暂停试运行并提示刷新重试，避免错误条件导致漏用规则。

默认审查整份合同，包括应当补充而原文缺少的条款。只有明确选择“仅审查选定条款类别”时，才按类别子集限制本次审查。付款规则不能因为合同没有付款章节就被忽略，也不能被用于不相干的责任条款后宣称已落实。

## 公共规则建议

保存完整改稿和修改理由，查看逐字段修改前后内容。现有建议可以继续编辑，实质修改会使原人工确认失效。

“运行正文、引用与依赖检查”实际核对公共基线、字段结构、正文缺项、真实来源、类型及依赖。发现问题时明确列出，不能只填写“通过”。核对人阅读本版内容和检查结果后，填写真实姓名并明确确认。

候选治理包可以导出供交流，并带出尚未完成的事项。“同意导出已核对建议”也不等于已执行公共回归，更不等于更新了正式资产。正式晋级仍须在知识治理流程中完成实际回归、批准和发布。本机姓名为操作者自述记录，不构成身份认证。

## 让规则落实到合同

在“合同任务”选择原 DOCX、合同类型、我方角色、审查立场和阶段，明确是否使用某客户规则，再创建任务。系统固定原件和规则版本；不能用后来编辑的草稿悄悄改变本任务口径。

“合同任务”和“工作区与备份”会显示文档生成环境，逐项说明是否找到合同转换、页面信息和逐页预览工具。缺项时可以继续维护规则、保存原件和准备修改安排；执行修订前会检查依赖，缺少时保留原件与安排并说明原因。配置完成后重启工作台，再点“重新检查文档生成环境”。工具已找到仍须实际生成、核对字体和每一页，不能直接作为交付接受。

下载 Agent 交接资料，交由具备本 Skill 的审查 Agent 完成合同实质审查并形成计划。交接资料包含原件定位、固定上下文、规则要求和处理记录契约。这里不会仅凭选择规则自动编造法律判断。

有客户规则时，审查 AI 阅读合同全文，逐条说明已落实、原文已满足、不适用或以批注保留的未明事项，并提供可核对证据。业务不适用、事实缺口或商业选择须在相关位置形成真实 Word 批注；未知事项不能写成已确认事实，不能只写报告或借无关批注跳过要求。规则未启用、有效期或用户明确限定条款组等确定排除，可依据实际解析理由说明。

该流程不以用户逐项再填确认人或点击批准为前置，其他有依据的修订继续执行。已有真实人工决定时，可用折叠入口补充记录；它不能代替应有正文修改或批注。页面“有处理事项待补全”表示归属、原文或批注证据尚缺，不等于必须再办人工审批。字段及兼容规则见 [客户规则处理记录](studio-task-dispositions.md)。

上传计划后运行真实修订。系统检查原文定位、修订、报告一致性及实际接受/拒绝结果。应修改正文的事项不能只用报告或批注交差。执行失败或证据缺口会保留为未完成状态，并提供具体原因。

生成后检查审阅版、接受修订版、拒绝修订版和报告的每一页。检查裁切、重叠、缺字、字体、表格与页眉编号、非目标格式以及接受/拒绝结果。已经用合格批注保留的未决业务事项，不要求先被解决才继续交付其他修订；正文、批注证据和文件质量必须通过检查。逐页核对、完整勾选检查项并由真实检查人明确确认后，任务才能标为可交付。

本轮已修复 macOS 随附渲染工具未找到系统中文字体而生成空白/方框的问题；修复只作用于渲染子进程，不改合同字体声明或系统设置。字体替代后的可读性不等于原字体精确保真。专业服务样例还发现：LibreOffice 对原稿已有的嵌套插入内删除标记显示不完整，修订稿继承了该显示限制，虽然接受、拒绝后的文本正确，审阅显示仍须在实际 Word/WPS 中核对。存在这种情况时，不勾选通过并宣称交付完成。

最终对外交付为修订合同和审查报告两份 DOCX。计划、执行记录、接受/拒绝副本及页面图像属于过程证据。下载按钮标为“待验收”的文件不能当作已经完成验收的最终交付。

## 数据与 Windows

“工作区”显示实际数据目录、只读状态及恢复提示。备份包含客户规则、快照、提案、未完成填写进度、合同任务和验证记录。备份内容须按合同材料管理。

恢复会校验完整性并写入新的独立目录，不覆盖当前工作区。核对新目录后再以它启动；保留原工作区直至确认恢复完整。只读启动允许阅读与试运行，不允许保存、确认、发布或执行任务。

Windows 的启动、固定解释器、离线依赖和原生验收步骤见 [Windows 离线运行包](studio-windows.md)。真实文档渲染还须准备渲染工具及所用中文字体；缺少这些条件时，交付仍未完成。
