# 知识资产治理与隐私边界

## 状态机

知识资产只能按以下顺序流转：

`candidate → lawyer_approved → regression_passed → active → deprecated`

只有 `active` 可进入正式审查。状态变化必须有审核人、审核时间、法律核验时间和回归证据；不得由运行时脚本自行晋级。

## 本地与 Skill 边界

原始合同、条款全文、客户信息、原始路径、合同族标识和原件哈希只保留在本地敏感数据区。Skill 只能保存脱敏、提炼并批准的知识资产以及公开来源的必要元数据。

候选 Skill 发布前扫描：

- 用户主目录绝对路径；
- 合同族标识和长哈希；
- 客户名称、项目名称和未脱敏主体名称；
- 原合同条款的大段逐字文本；
- 未获批准的来源或模块。

发现任一项即阻断安装。

## 来源层级

优先使用现行有效的法律法规、司法解释和官方典型案例；其次使用可核验的高质量律师实务文章、真实历史修订和失败案例。文章只提炼观点与判断方法，不整篇打包。

每项来源至少记录：来源 ID、作者或发布机关、标题、来源链接或本地登记、法域、发布日期、核验日期、来源状态和律师批准状态。知识性质标记为 `legal_boundary`、`judicial_tendency`、`risk_control`、`negotiation` 或 `client_policy`。

仅通过搜索结果确认标题、账号或摘要的微信公众号文章须标为 `wechat_practice_article_discovery`，只能作为后续取证线索。未取得并核验正文前，不得进入原则卡、模块或触发器的 `source_ids`，不得支持法律结论。

## 代表合同与母版

代表合同适格度自动分值仅用于缩小人工审阅范围。法律明显过时、文本不可可靠提取、内部冲突、无法脱敏、来源不明或只有签署扫描件且无可编辑版本的，均不得进入母版。

每类3至8个批准合同族分别承担基础骨架、我方强保护、对方强保护、平衡、特殊场景和反例。完整 DOCX 最多三份，其他差异进入条款模块。内部批准合同族少于三个的类型保持暂行、未激活。
